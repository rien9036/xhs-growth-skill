# Versioning & Compliance

## Why this file exists

平台变化速度快。Skill 需要保留稳定的方法论，同时避免把历史产品、门槛和经验阈值固化为事实。

## Must verify before answering

以下内容若用户要求具体数值/规则，先核验当前官方信息：

- 账号类型和认证
- 店铺类型与费用
- 广告产品、投放目标和入口
- 私信限制
- 线索收集工具
- 外部导流政策
- 直播权限
- 账号关联能力
- 内容字数/媒体限制
- 社区规范
- 违规处罚
- 搜索/推荐产品
- 商业合作平台
- DMP/数据产品
- 当前算法官方定义

## Stable methods that can be reused

- 从业务目标反推内容
- 需求与关键词研究
- 定位测试
- 内容生产 SOP
- 漏斗诊断
- A/B 测试
- CAC / ROI / LTV
- 单账号验证后规模化
- 团队知识库和复盘

## Compliance principles

### Do
- 真实身份和业务
- 原创内容
- 合法素材
- 明确广告/商业披露（如要求）
- 官方允许的咨询、留资、店铺和广告工具
- 用户同意和隐私保护
- 当前规则核验

### Do not
- 刷数据
- 伪造评论
- 诱导虚假互动
- 抄袭搬运
- 隐藏联系方式绕过规则
- 用谐音/图片编码等规避检测
- 通过多账号规避封禁
- 使用自动私信工具骚扰用户
- 虚构收益、案例或身份

## Versioning rule

建议每次平台重要更新后：

1. 更新此文件中的规则核验项。
2. 检查本 Skill 的内部方法 是否引用具体门槛。
3. 把已失效平台功能删除或标记 deprecated。
4. 在 README 或 release notes 中记录变化。
