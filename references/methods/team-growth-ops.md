# Team Growth Operations

> Internal method reference for `xhs-growth-skill`. This file is not an independent Skill.

**Use when:** 要搭团队、分工、培训、知识库或绩效机制

**Scope:** 角色分工、SOP、培训、知识库与绩效

**Method intent:** 为小红书获客团队设计角色分工、SOP、培训、知识库、沟通、绩效与迭代机制，使有效增长方法可以被团队复制。

## Goal

让增长能力从“某个人很会做”变成“团队可以稳定执行”。

## Start small

在业务模型未验证前，团队尽量精简。

优先明确责任而不是堆人数。

最小团队可按业务需要覆盖：

- 内容/运营
- 设计/拍摄（如需要）
- 销售/线索跟进
- 负责人/增长分析

一个人可以承担多个角色。

## Operating system

### 1. Role definition
每个岗位明确：
- 输入
- 输出
- SLA
- 指标
- 上下游
- 决策权限

### 2. SOP
至少沉淀：
- 需求研究
- 选题
- 内容制作
- 发布
- 评论/咨询处理
- 线索交接
- 数据记录
- 周复盘
- 异常处理

### 3. Training
采用“培训 → 实操 → 考核 → 反馈 → 再训练”。

考核基于真实任务和作品，而不仅是记忆知识点。

### 4. Knowledge base
持续记录：
- 有效选题
- 失败选题
- 封面/标题测试
- 用户高频问题
- 销售异议
- 平台规则变化
- 案例
- SOP 版本

### 5. Communication
建立短周期同步机制：
- 今日异常
- 用户新需求
- 内容反馈
- 线索质量
- 规则变化

### 6. Performance
绩效不能只看发帖数。

按角色选择：
- 内容交付质量
- 有效内容率
- 高意向互动
- 有效线索
- 响应时效
- 成交/收入
- 复盘质量
- SOP 改进

避免让单一指标诱导刷数据或牺牲内容质量。

### 7. Continuous improvement
每周只推动少量优先实验，并把结果写回知识库。

## Outputs

- 团队结构
- RACI/责任表
- 每周运营节奏
- SOP 列表
- 培训计划
- 知识库结构
- 绩效指标
- 复盘机制

## Management principles

- 人岗匹配
- 流程尽量简单
- 用数据和作品评估
- 及时反馈
- 让优秀实践沉淀为资产
- 团队制度不得建立在刷量、平台违规或用户骚扰上
