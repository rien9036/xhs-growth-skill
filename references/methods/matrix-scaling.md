# Matrix Scaling

> Internal method reference for `xhs-growth-skill`. This file is not an independent Skill.

**Use when:** 单账号/单内容模型已经跑通，希望扩大规模

**Scope:** 已验证模型的多账号与规模复制

**Method intent:** 在单账号或单内容获客闭环验证后，设计合规的多账号、多栏目、多素材和团队规模复制方案。

## Goal

把一个已经验证的获客单元扩大，而不是把大量未验证账号同时铺开。

## Scaling unit

先定义最小可复制单元：

**目标人群 + 内容方向 + 获客入口 + 转化路径 + 交付能力 + 核心指标**

当这个单元能重复产生有效线索/成交，才进入规模复制。

## Preconditions

- 自然或付费曝光已得到验证
- 有真实商业意向
- 有有效线索
- 有成交或明确的下游价值
- 内容生产可重复
- 交付有余量
- 当前平台允许相关账号和业务模式

## Scaling dimensions

合规的规模化可以来自：

1. **更多内容**：同一需求的不同原创角度
2. **更多人群**：为不同细分用户建立差异内容
3. **更多地域**：本地业务按实际服务能力拆分
4. **更多角色**：专家、案例、品牌、产品等不同真实角色
5. **更多账号**：仅在业务确有分工、主体合法、内容独立时使用
6. **更多渠道**：自然、搜索、付费、店铺、直播等当前允许方式

## Procedure

### 1. Prove one unit
要求连续多次结果，而不是一次爆款。

### 2. Document the SOP
记录：
- 选题来源
- 内容模板
- 制作周期
- 发布检查
- 意向识别
- 线索承接
- 销售转化
- 数据复盘

### 3. Choose one scaling axis
一次优先扩大一个维度，避免同时增加账号、预算、选题、人群，导致无法判断原因。

### 4. Differentiate by value
不同账号/内容应有真实差异：
- 用户
- 场景
- 专业角色
- 地域
- 产品
- 叙事角度
- 素材

不要通过简单改词、换边框等方式规避重复内容检测。

### 5. Monitor cannibalization
检查多个账号/内容是否：
- 争抢同一受众而没有增量
- 增加管理成本
- 降低内容质量
- 超出销售/交付能力

### 6. Set kill criteria
表现长期不达标的实验单元应停止，但不得用新账号绕过处罚或封禁。

## Outputs

- 最小复制单元
- 规模化前置条件
- 账号/内容角色矩阵
- 产能需求
- 质量标准
- 风险清单
- 停止条件

## Compliance

多账号策略不得用于规避封禁、限制、广告政策或身份要求。所有账号均应符合平台当前规则，内容需要独立价值和真实主体。
