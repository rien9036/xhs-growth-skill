# Account Launch & Positioning

> Internal method reference for `xhs-growth-skill`. This file is not an independent Skill.

**Use when:** 不知道从哪个方向开始、定位如何验证或账号怎么表达

**Scope:** 方向测试、定位收敛、主页表达与视觉基线

**Method intent:** 设计小红书获客项目的方向测试、定位收敛、主页表达和视觉基线。适用于新项目起步、定位不清、账号表达混乱或需要重新验证赛道的情况。

## Goal

把“我要做一个账号”转换为一组可验证的业务假设，而不是先写一个看起来漂亮但未经验证的定位。

## Inputs

优先获取：

- 产品/服务
- 价格区间
- 毛利或可接受 CAC
- 交付地域
- 目标客户
- 已有客户案例
- 创作者/团队优势
- 可持续产出的内容类型
- 当前账号数据（如已有）
- 平台当前对该品类的限制

信息不足时，不额外制造大量变量；先基于已有信息提出最小测试方案。

## Positioning frame

用四个约束检查方向：

1. **用户要看**：目标用户是否存在真实需求和内容消费动机。
2. **我们能做**：团队是否有产品、经验、素材、表达或交付优势。
3. **平台允许**：内容与商业模式是否符合当前规则。
4. **市场已验证/可验证**：是否能看到同行、相邻品类或真实搜索信号；若没有，需要设计验证而不是直接假设是蓝海。

再补充“自有资产”：

- 我是谁
- 有哪些经历
- 有哪些可信成果
- 我愿意长期分享什么
- 相比替代方案有什么优势

## Procedure

### 1. Define the business
一句话写清：
**为谁 → 解决什么问题 → 提供什么产品/服务 → 希望用户采取什么动作。**

### 2. Generate direction hypotheses
通常提出 2–4 个，不宜过多。例如按：
- 人群
- 场景
- 痛点
- 地域
- 产品
- 身份/专业能力

形成不同方向。

### 3. Validate with evidence
为每个方向检查：
- 搜索需求是否存在
- 最近是否有相关内容获得互动
- 评论区是否出现真实问题/购买意向
- 是否能找到小体量账号或新内容的有效样本
- 自己是否能持续生产
- 产品是否承接得住

### 4. Design a small test
每个方向用少量内容进行变量尽量单一的测试。优先固定其他条件，只改变一个关键变量，如选题、人群或封面表达。

### 5. Converge positioning
不要只看点赞。综合：
- 点击/阅读
- 收藏/评论
- 高意向评论
- 私信/官方留资
- 有效线索
- 成交
- 内容生产成本

选择更接近业务结果的方向。

### 6. Package the account
定位收敛后，再统一：
- 名称
- 头像
- 简介
- 主页视觉
- 核心内容栏目
- 置顶内容
- 业务承接入口（仅使用当前规则允许的方式）

### 7. Establish a visual baseline
连续测试若干视觉方向，记录点击与阅读表现；选择有效模板，但定期验证是否出现审美疲劳。

## Outputs

至少输出：

- 业务定义
- 2–4 个定位假设
- 每个假设的证据与风险
- 小样本测试表
- 推荐定位
- 主页表达草案
- 视觉测试方向
- 需要核验的平台规则

## Avoid

- 把“粉丝最多”当作“最接近商业结果”
- 一开始就追求独特到无法验证的定位
- 直接复制成熟大号的结果假设
- 用过时的平台权重、养号、认证门槛当作当前事实
- 通过非真实行为“模拟真人”来操纵账号信任
